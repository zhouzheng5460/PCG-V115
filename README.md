# TownForge

> 现状（2026-11-09）：单一生成器 **F3 规则城市** + 单一 three.js 视口（透视 / 正交顶视）。
> 架构与改动见 [`docs/F3_V2_ARCHITECTURE.md`](./docs/F3_V2_ARCHITECTURE.md)，
> 性能与禁区机制见 [`docs/F3_PERF_ZONE_PLAN.md`](./docs/F3_PERF_ZONE_PLAN.md)。
> 下面关于 legacy / Planner 的描述是历史版本，仅作背景。

> **接手开发请先读 [`AI_HANDOFF.md`](./AI_HANDOFF.md)** —— 开关矩阵、当前进度、待办与雷区。
> 分阶段完整叙事见 [`DEVELOPMENT.md`](./DEVELOPMENT.md)。

把 [TownGeneratorOS](https://github.com/watabou/TownGeneratorOS)（Medieval Fantasy City Generator 的开源源码）改造成一个可交互编辑、并能导出 glTF/GLB 的城市生成器。

原项目是 Haxe + OpenFL 的桌面/Flash 风格 2D 生成器，算法写死在一次性 build 里、路宽是三个硬编码常量、没有任何导出能力。这个工程把生成内核逐文件移植到 TypeScript，在此之上加了三件事。

## 三个改造点

### 1. 禁建区：可绘制的"禁止创建内容"范围

支持矩形 / 圆 / 自由多边形三种画法。禁建区在三个层面生效，保证边界既精确又不会把城市搞散：

| 层面 | 做法 | 效果 |
| --- | --- | --- |
| 地块 | 计算地块与禁区交集面积占比，超过阈值（默认 35%，可调）整块标记 `blocked` | 整块地不生成任何内容 |
| 路网 | A* 建图时丢弃采样后落在禁区内的边（`edgeInsideZones`） | 路不会穿过禁区，但可以贴着禁区边界走 |
| 建筑 | 对每个建筑多边形做布尔差集（`polygon-clipping`） | 压线的建筑被精确切在禁区边界上 |

设计上有个关键取舍：**地块形状本身不裁剪**。早期版本用多边形布尔运算把地块切掉，结果城墙跟着变形、城门悬空、A* 直接无解。地块是城市的结构骨架，禁掉"内容"就够了 —— 边界精度交给建筑级裁剪来保证。

另外，禁区整块占用的地块**仍然参与 ward 随机分配**（只是最后不产出几何）。否则少一块地会让整条随机序列错位，城里其他所有地块的类型都会跟着变。

### 2. 路宽与拓扑点可编辑

原版的路宽其实是"地块内缩后留下的缝"，藏在 `Ward.MAIN_STREET / REGULAR_STREET / ALLEY` 三个常量里。改造后：

- 常量变成 `model.style` 参数，面板上可实时调主干道 / 街道 / 巷道三档宽度；
- `arteries` 从 `Polygon` 变成带 `width` 的 `Artery`，地块内缩量按**该边所属道路自己的宽度**计算；
- 点击任意一条路可以单独调宽（`widthOverrides`），渲染、导出、地块内缩三处同步；
- 打开"显示拓扑点"后可以直接拖拽路口顶点。拖动时只移动顶点并重绘（建筑暂时隐藏），松手后从坐标快照重建整个下游管线。

拖点后的重建不需要重跑 Voronoi：`Model` 被拆成 `buildPatches`（一次）和 `buildAll`（可重复），中间存一份顶点坐标快照，每次重建先复位坐标再跑。

### 3. GLB 导出

`buildTownMeshes()` 把模型转成 3D 网格，`exportGLB()` 手写 glTF 2.0 二进制（不依赖 three 的 exporter，Node 和浏览器都能跑）。

导出内容按语义分组命名，方便在 Blender / C4D / UE 里单独选中替换材质：

- `ground` 地面（城内）
- `street` / `street_edge` 主干道（按各自宽度成带，带深色路缘）
- `<ward类型>` 建筑，拆成 `_roof`（屋顶）和 `_wall`（墙面）两部分
- `wall` 城墙（按段生成后合并）+ 塔楼 + 城堡墙

坐标系：地图 `(x, y)` → 3D `(x, 0, y)`，高度沿 +Y，与 2D 编辑器俯视一致。

## 4. 现代城市：把"放什么"整层换掉

原来的内容层是 13 种中世纪 ward（行会、市场、教堂、贫民窟…），路面就是一条深色带。现在新增 `mode: 'modern'`，用一整套现代城市的内容层替换它——**底层空间链一个字没动**：

```
buildPatches()  →  Topology（顶点建图 + Dijkstra）  →  getCityBlock()（地块内缩）
        ↑                        ↑                              ↑
   Voronoi 分地块            拓扑寻路                    insetForEdge()
                                                                  ↓
                                                   道路横断面（同一函数推导）
```

关键约定：**道路中线就是地块边**，路宽就是地块内缩让出来的那道缝。所以横断面不是"另画一条路"，而是把这个缝隙按比例切成人行道 / 绿化带 / 车行道。这样路面、人行道、建筑红线永远严丝合缝，拖点或改路宽后自动跟着走。

### 4.1 道路：横断面 + 独立路口 + 标线

参考 [three-roads](https://github.com/vibe-stack/three-roads) 的"横断面 → 条带 + 独立路口几何"结构，但路口不手写，直接从路网图里读（度数 ≥ 3 的顶点）。

横断面按**比例**算，因为 1 世界单位 ≈ 7 m，写死米数没有意义：

| 部件 | 取法 |
| --- | --- |
| 人行道 | 红线宽 × 28%，clamp 到 0.16~0.5 |
| 绿化带 | 红线 > 1.5 时取 5% |
| 中央分隔带 | 仅主干道且红线 > 2.4 时取 4.5% |
| 车行道 | 余量，且保证 ≥ 红线的 42%（不够就先砍绿化带再砍人行道） |
| 车道数 | `2 × round(车行道 / 0.9)`，夹到 2~6；车行道 < 0.55 时降为单车道 |

路口是独立几何：车行道圆盘（`rIn = max(半车行) × 1.18`）+ 按方向锥开口的人行道转角环（`rOut = max(半总宽) × 1.02`）。边两端的条带用 `pad = r × 1.2` 截断，不斜插进路口。

标线分四层靠高度差避免 z-fighting：路面 0.012 / 绿化带 0.019 / 人行道 0.020 / 标线 0.032。主干道画双黄中心线 + 车道虚线（虚线 0.5 / 间隔 0.42），次干道画单白虚线，每个路口端画斑马线 + 停止线。

> 踩过的坑：路口人行道转角环如果"逐格交替 push 内外圈"，多边形会自交，earcut 会吐出横跨图形的黑色碎片。必须先把内圈连续走完再折回外圈。

### 4.2 土地用途：同心环 + 分位数

不是随机贴标签，而是按经验规律分区，再用**分位数**而不是绝对半径分档（这样 6 块地和 24 块地都能分出中心/中间/外围）：

| 分位 | 用途 |
| --- | --- |
| q < 0.18 | CBD（玻璃塔 + 裙房） |
| q < 0.42 | 商业（临主路） / 公共设施 / 住宅 |
| q < 0.72 | 住宅（临主路则商业） |
| q < 0.88 | 住宅 / 公园 / 地面停车 |
| 其余 | 工业 / 绿地 |

最后做**保底补位**：城里必须有 CBD、公园、地面停车、公共设施、工业各至少一个，缺哪个就从相邻档里换一块过来。半径基准是"原点到地块质心"，不能用 `model.center`（那是随种子漂移的参考顶点，第一版就因为它把十五块地全判成工业区）。

### 4.3 地块内容：先摆后裁

每个用途有独立规划函数，共同点是**建筑原型按世界坐标摆轴对齐矩形，再与可建区求交**，面积占比 < 52% 就丢弃。这样出来的楼永远规整、永远压在红线内：

| 用途 | 内容 |
| --- | --- |
| CBD | 7~13 层玻璃塔 + 1.3~2.2 层裙房 + 副楼 + 硬质铺装前场 |
| 商业 | 2~3 栋沿街板楼 + 后场停车 + 人行道铺装 |
| 住宅 | 行列式板楼 + 院通道 + 地面停车 + 绿地 |
| 工业 | 主厂房 + 混凝土堆场 + 货运停车 + 铁艺围栏 |
| 公共设施 | 主楼 + 前广场 + 树列 + 旗杆 |
| 公园 | 园路 + 交叉圆盘 + 喷泉 + 长椅 |
| 地面停车 | 沥青场地 + 车位阵列 + 绿化岛 |
| 绿地 | 草地 + 沿边林带 + 内部散树 |

凹地块的 `buffer()` 会返回自交多边形，这里做一次自身求交让它规范化（`intersect(ring, ring)`）；布尔运算全部走量化坐标，避免扫描线在近似共线处抛 `Unable to complete output ring`。

### 4.4 街网形态：从正交格网到张量场流线

现代模式的第一步（切地块）有四种形态，侧栏「布局」切换，只影响"怎么切"，切完都是同一份 `Patch[]`，后面的内缩 / 横断面 / 地块内容 / GLB 完全复用：

| 布局 | 做法 | 参考形态 |
| --- | --- | --- |
| 方格网 `grid` | 正交层级格网 + 低频正弦位移，格线索引决定道路等级 | 曼哈顿、芝加哥 |
| 场线 `field` | 格网整体过一个旋涡映射（扭转角 `amp·exp(-r²/2σ²)`），街道连续弯曲但格点对应关系不变 | 巴塞罗那扩展区 |
| 放射环 `radial` | 同心环 + 放射辐条，环半径带谐波起伏，可叠 `spiral·log(r/r_in)` | 华盛顿、堪培拉 |
| 张量场 `tensor`（默认） | 方向场 → 流线 → 平面图 → 面，见下 | RogueCities / symbios-tensor |

张量场这条链在 `src/town/field/`：

```
FieldSource[]  ──►  TensorField  ──►  traceFamily(主/次)  ──►  buildArrangement  ──►  Patch[]
(基准/边界/中心/禁区轮廓)   (无迹二阶张量)      (RK4 + Jobard–Lefer 播种)      (求交→半边→面)
```

几个关键决定：

- **必须是张量而不是矢量场**：街道方向无向，0° 与 180° 是同一个方向。用 `T = [cos2θ, sin2θ]` 累加再求主特征向量，θ 与 θ+π 天然等价，次方向自动成为正交方向。直接对角度做加权平均会把 0° 和 90° 平均成 45°。
- **场源配比**：全局基准（0.9）必须压住局部场源，否则次方向全部收敛到中心，整城退化成"环 + 辐条"。边界切向（半径 0.3R）、中心旋涡/放射（半径 0.34R）、禁建区轮廓（`path`）都只负责"把街道带弯"。
- **线距靠播种控制**：抖动网格撒种 + 每接受一条线就沿法向 ±spacing 补种（Jobard–Lefer），再跑两轮"扫描补洞"；与已有线贴合超过 45% 的候选直接丢弃 —— 这类平行孪生线会切出针尖碎面，碎面一丢就断网。
- **闭环要掐断**：旋涡场里流线会绕圈画回来，绕一圈就把城切碎。追踪时用网格哈希记录本线足迹，撞到 6 步以前的点即停。
- **共享顶点池**：求交后按 1e-3 量化建顶点池，相邻面拿到的是同一个 `Pt` 对象。`buildRoadNet` 靠对象身份配对两侧地块，所以不需要再焊接。
- **端点吸附（snap）**：线头常常停在另一条线旁差 1~3 单位的地方，那是度数为 1 的悬挂节点，路网会断开。把线头投影到邻近线段/轮廓上，让它变成 T 型连接。
- **补洞**：平面图偶尔漏一个面（顶点处共线退化），用"面的总面积 vs 轮廓面积"判断，少了就用布尔差补回来，且要求补出来的环顶点 100% 命中既有顶点 —— 否则补出一块对不上边的地，那条路只剩一侧，反而切断路网。

### 4.5 方向控制线：让街道顺着你画的线排

张量场唯一需要用户直接操作的东西。用户不需要理解张量，只要在图上画一条折线，意思是"这一带的街道朝这个方向排"：

```
FieldGuide(折线) ──► guideToSource() ──► type:'path' 场源 ──► 与基准/边界/中心一起合成
```

- **一条线管多宽**：影响半径 `0.26R`（约 3 个街区宽），`w = strength·exp(-(d/r)^1.6)`，在线两侧一个带内生效，离开带就退回全局基准方向。2D 上画成半透明蓝色宽带，就是这条半径。
- **强度为什么要 5 倍**：张量场在 2θ 空间做加权平均，两个方向合成后的角差会被"折半"。实测（基准 57.6°、线 18°）：权重比 1.2 : 0.9 时场只转到 32.5°，比 9 : 1 时仍有 2.7° 残差 —— 强度不够时用户会觉得"画了没反应"。5 倍（默认 strength 0.8 → 权重 4.0，约 4.4 : 1）把残差压到 5° 以内，同时保留指数过渡带。
- **回归测试量的是"路网走向 vs 线的夹角"**：带内所有路边按长度加权，夹角要**按 90° 折回**——张量场本来就产出两族正交街道，垂直那族不是错位。按 180° 折会把一半的边算成 90° 偏差，均值永远卡在 45°，看起来像"没生效"。
- **边界附近线会输**：轮廓那一圈街道必须顺着城界闭合，所以贴着 `0.85R` 往外画的线只能部分生效（实测城内 3.7°、外侧 14.4°）。这是形状约束，不是 bug。
- 方向线改的是**切块**（场 → 流线 → 面），所以必须整城重生；禁建区只是裁剪，两者走的是不同路径。

### 4.6 街道设施：按路布点

行道树和路灯不挂在地块上，而是沿主干道人行道中线布置（间距 2.5 / 5.0），灯臂朝向路心。硬上限 300 棵树 / 240 盏灯，改路宽或拖点后自动跟着路走。

### 4.7 一个 Scene，三个消费者

2D 编辑器、three.js 预览、GLB 导出读的是同一份 `Scene`（`src/scene/types.ts`）：

```ts
SurfaceFeature  { ring, mat, y }        // 地面/铺装/标线，按 y 从低到高铺
SolidFeature    { ring, y0, h, kind }   // 建筑体块，挤出 + 屋顶分材质
PropFeature     { kind, at, rot, scale} // 树/灯/长椅/喷泉/车…
PathFeature     { pts, width, mat }     // 内部道路、园路、围栏（可带高度成墙）
```

`Model.revision` 每次重建 +1，两个视图据此判断是否重建场景，不用手动通知。调色板集中在 `src/scene/palette.ts`，2D 用 `css()`，3D 用 `MAT[]`，不会出现"2D 看到的和 GLB 里不一样"。

导出分组：`ground` / `road/{surface,sidewalk,junction,marking}` / `lot/<用途>` / `street/{avenue,furniture,lighting}`。

## 跑起来

```bash
npm install
npm run dev        # http://localhost:5173
```

```bash
npm run test       # 53 次生成回归 + 确定性 + 重建幂等 + 禁建区 + 路宽 + 拖点 + 现代城市场景断言
npx tsx test/glb.test.ts   # GLB 结构校验 + 绕序自检 + 软件光栅化出图
npm run build      # 产物在 dist/
```

## 操作

| 操作 | 说明 |
| --- | --- |
| 滚轮 / 右键拖动 | 缩放、平移 |
| 点"矩形/圆/多边形"后拖拽 | 画禁建区（多边形双击闭合，Esc 取消） |
| 点"画方向线"后逐点点击 | 画方向控制线（双击结束，只影响张量场布局） |
| 勾选"显示拓扑点"后拖动圆点 | 改路网走向 |
| 点击道路 | 选中后单独调宽度 |
| 顶部"三维预览" | three.js 实时预览（和 GLB 同一套网格） |
| 顶部"导出 GLB" | 下载 `.glb` |

URL 参数可以复现状态：`?n=24&seed=12345&zone=1&verts=1&mode=modern&markings=0&furniture=0`。

侧栏里的开关直接控制场景内容：**风格**（现代城市 / 中世纪，切换会重跑整套生成）、**布局**（方格网 / 场线 / 放射环 / 张量场，只在现代城市下出现）、**道路标线**、**行道树 / 路灯**。关掉标线或设施后 2D 与 3D 会同步刷新，导出的 GLB 也按当前开关生成。

地址栏参数：`?layout=grid|field|radial|tensor`、`?mode=medieval`、`?n=24`、`?seed=8`、`?zone=1`、`?guides=1`（放两条示例方向线）、`?markings=0`、`?furniture=0`。

  types.ts      Surface / Solid / Prop / Path + LandUse

## 与原版的差异

逐文件对照翻译，几何算法、随机序列、难度参数都保持原样，同种子可以复现同一座城。有意的偏离只有四处：

1. `Polygon.buffer()` 里处理自交的循环，原版理论上可能死循环，这里没有改动逻辑但外层加了收敛保护；
2. `Ward.createOrthoBuilding()` 的 `while(true)` 加了 64 次迭代上限，超限返回原多边形；
3. 路宽从常量改为参数（默认值与常量一致：2.0 / 1.0 / 0.6）；
4. `Rng.reset` 对 seed ≤ 0 做了保护（原版 seed=0 时整个随机序列会退化为 0）。

原项目源码保留在 `../TownGeneratorOS-master/` 作为对照。

## 已知限制

- 禁建区如果整个盖住城市中心，广场会被放弃（城市仍能生成，只是没有中央集市）；
- 拖动顶点不校验地块自交，把顶点拖过对边会得到扭曲的地块；
- 城墙高度、塔楼尺寸目前是固定值，没有开放为参数；
- 现代模式的路口只有"圆盘 + 方向锥开口"一种形态，没有做渠化岛 / 转向车道；
- 建筑是体块级（没有窗、阳台、屋顶设备），靠屋顶 / 墙面分材质来分区；
- 大规模城市（`n=40`）导出约 2.5MB，浏览器端导出仍在 1 秒内完成。
