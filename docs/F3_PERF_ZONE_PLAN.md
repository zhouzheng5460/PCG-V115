# F3 性能与禁区避让 · 现状、修复与后续计划

> 测量口径：`npx tsx .scratch/prof.ts <半径> <种子>`（Node 22 / 单线程，同机交替重跑取第二次）。
> 固定场景 **seed 682063530**，1 世界单位 = 7 m。
> 复测开关：`F3_TC=1` 打印各阶段耗时，`F3_DEBUG=1` 打印阶段④分项，`F3_MK=1` 打印标线段数。

---

## 1. 结论摘要

| 规模 | 半径 | 修复前 | 修复后 | 倍数 |
|---|---|---|---|---|
| 小城 | 60 | ~28 s | **1.9 s** | 15× |
| 中城（默认） | 90 | **92 s** | **6.0–6.4 s** | ~15× |
| 大城 | 120 | ~150 s | **13.5 s** | ~11× |

**根本原因只有两个，都在标线这一步：**

1. `roadgeom.ts` 把**整张并好的车行面**（一片 3179 顶点的多边形）传给了标线裁剪，
   于是 4774 段标线每一段都要跟这片巨面做一次 `polygon-clipping` 布尔 —— 65 s。
   而同一个函数上方 8 行的注释早就写着"不要传 B[0]，要传拆开的小片（31.8 s）"，
   代码却传的是 `B[0]`。这是一处**回归**，不是算法问题。
2. 换成小片之后仍然 4 s 级别，因为"确实跨界的少数标线"之外，
   其余标线也在做逐点/逐边判定：点内测试打的是 3179 顶点的环（0.18 ms/次），
   线段相交测试是 80 点 × 几十条边。现在换成**边界边索引 + y 带射线法 + 小标线顶点判内**
   三级快路径，实测 640–1200 ms。

## 2. 修复内容（已落地）

### 2.1 裁剪输入：整张车行面 → 拆开的小片

`src/f3/roadgeom.ts`

```diff
-  const mk = buildMarkings(graph, B[0], { secOf, jApp, blockers: junction, faces, jArcs });
+  const mk = buildMarkings(graph, [...carriage, ...junction], { ... });
```

`B[0]` 是**所有道路并成的一片**（3179 顶点、25 万 m²），bbox 过滤对它完全失效。
拆成 `carriage`（每街一片，38 片）+ `junction`（每个路口一片，83 片）之后，
一段标线平均只命中 **1.5 片**，每片几十个顶点。

| 指标 | 修复前 | 修复后 |
|---|---|---|
| 每段标线候选片数 | 1（巨面） | 1.51（中位 1） |
| 单片顶点数中位 | 3179 | 30 |
| 标线裁剪耗时（r=90） | 65 s | 0.36 s |

### 2.2 裁剪算法：三级快路径（`src/f3/markings.ts`）

`clipMarksToAsphalt` 原来对每段标线**无条件**做布尔。但 99% 的标线本来就整条躺在
车行面内部（它们是按车道模型偏移出来的，不是随机撒的）。现在的判定顺序：

1. **小标线（< 6 m，占八成）**：逐顶点判内外。全在里 → 直接留；全在外 → 直接丢；
   只有部分在里（全城 < 10 段）→ 才走布尔。
   一条 15 cm × 1.5 m 的白条不可能"四个角都在沥青里、中间却跨出车行面"。
2. **长标线**：先用**边界边索引**判断"有没有沥青边界边穿过它"。
   没有穿过 → 一个点内测试定生死，零布尔。
3. 上述都不成立 → 原来的布尔裁剪（每城几十段）。

配套的两个索引（`AsphaltBoundaryIndex`）：

- **边界边网格**：4 世界单位（≈28 m）一格，边按 bbox 入桶；每条边的 bbox、
  所属片号**预计算**（同一条边会被几百段标线反复问到，原来每次都重算）。
- **y 带射线法**（`insideAny`）：点内测试只扫该点所在横带的边，不再遍历 3179 个点。
  实测 0.18 ms → 0.008 ms 量级；再叠一层"按 2 单位格子缓存内外结果"。
  > 注意：不能用"只测质心"代替。奇偶法必须按**片**分别计数，
  > 否则相邻两片的边界会被算成一次穿越，结果随机翻转。

### 2.3 副产品：可观测性

`F3_TC=1` 现在会打印标线内部三段耗时（生成 / 裁到沥青 / 让开路口）和
"快路径 vs 布尔"的段数；`F3_DEBUG=1` 打印阶段④里"建筑布局 / 地面"的分项。
**改这一块之前先开这两个开关**，否则又会凭感觉优化。

## 3. 现在的耗时结构（修复后）

r=90（62 街区 / 805 地块 / 2234 栋楼）：

| 阶段 | 耗时 | 占比 | 说明 |
|---|---|---|---|
| ① 张量路网 | 50 ms | 1% | 流线追迹 + 建图 |
| ② 道路几何 | 2.0 s | 33% | 四级断面并集 / 圆角 1.0 s、图层派生 0.6 s、**标线 0.36 s** |
| ③ 街区 | 40 ms | 1% | 场地 − 路网面 |
| ④ 地块 + 建筑 + 地面 | 4.3 s | 65% | **地面 2.7 s** / 建筑布局 0.5 s / 切分与用途 1.1 s |

r=120（111 街区 / 1395 地块 / 3896 栋楼）：总计 13.5 s，其中 ④ 8.9 s、② 4.3 s。
**规模翻一倍，时间翻两倍**（超线性）—— 因为 ④ 里每块地要做 6~8 次小布尔，
块数涨 1.7 倍、单块复杂度也涨。

## 4. 禁区避让（已接入 F3）

### 4.1 机制：从**生成边界**里扣掉，而不是生成完再裁

```
CitySpec.zones + zonePadM
        ↓ planZones()
生成边界 = 城市边界 − (禁区外扩 zonePadM)
        ↓ 张量路网 → 道路面 → 街区 → 地块 → 建筑
禁区净区 → emitZoneGround()：按用途铺 硬地/公园/林地（含树），面积入账
```

为什么不是"生成后裁":

- 裁 = 事后擦掉：路在禁区边缘留一排断头、地块被切成楔形、建筑压边界；
- 扣边界 = 根本没长：路网、街区、地块、建筑全在净区里生长，边界自然贴合。

### 4.2 实测（r=90，中央圆禁区 r=154 m）

| 指标 | 无禁区 | 有禁区 |
|---|---|---|
| 街区 | 62 | 47 |
| 建筑 | 2234 | 2103 |
| 质心落在禁区内的道路面 | — | **0 / 3830 片** |
| 生成耗时 | 6.0 s | 5.8 s（**没有额外开销**） |
| 禁区铺装 | — | 73 835 m² 草地 + 树 |

回归：`test/glb.test.ts` 断言"禁区铺装进场景且材质正确"；
`test/layers.test.ts` 断言"禁区里的树受植物图层控制"。

### 4.3 已知限制（写在这里，避免下次当成 bug）

1. **只保留最大的一块净区**。禁区把场地切成几块时，其余块不生成（notes 里报出面积）。
2. **不重路由**。边界处是尽端路，不是"绕一圈接上"——真正的重路由需要图级别的障碍传播。
3. **让距是硬边界**，不是"离得越近越少生成"。
4. 禁区与城市边界相交时，禁区外侧那一圈会被一起扣掉（禁区通常不该压在红线上）。

## 5. 后续优化计划（按性价比排序）

每条都带**验收判据**，不要只写"优化一下"。

### P0-1 地面层（3.9 s / 65%）—— 目标 ≤ 1.5 s

- **现状**：`groundForParcel` 每块地维护 `remaining`，用 6~8 次 `safeIntersect` /
  `safeSubtract` 逐个认领（前场 / 停车 / 绿化 / 岛）。805 块 × 平均 4 次布尔。
- **做法**：
  1. 把"认领"从布尔改成**矩形裁剪 + 一次性残差**：所有语法构件（前场、停车带、L 形绿化）
     都在局部 UV 坐标系里是矩形，可以直接用矩形裁剪多边形（Sutherland–Hodgman），
     不需要 polygon-clipping；只在最后算一次残差。
  2. `solveParking` 结果按"停车区几何指纹"缓存（同一份布局在换种子时经常重复）。
- **验收**：r=90 阶段④ ≤ 2.5 s；`test/f3-layout.test.ts` / `f3-landuse.test.ts` 全绿；
  停车位数与绿化面积变化 < 3%。

### P0-2 断面并集 / 圆角（1.0 s）—— 目标 ≤ 0.4 s

- 四层 B0..B3 各自 `unionPolys` 一遍，再做圆角化。四层是**同一族折线**，
  可以一次并集 + 一次偏移得到，不必四遍。
- **验收**：`test/f3-road.test.ts` 的"层间重叠 0 m² / 转角圆弧"断言不变。

### P1-1 分块增量重算（交互体验，不改总耗时）

- **问题**：改一个参数 = 整城重算 6 s，期间 UI 只有一个遮罩。
- **做法**：把 `runF3City` 按街区切段，利用 `requestIdleCallback` / 分帧 yield，
  生成到哪块就先把哪块 push 进场景（渐进式）。移动镜头时用户先看到路网与中心区。
- **验收**：任意改参后 **< 300 ms 出第一帧**（路网可见），总时长不变。

### P1-2 Web Worker 化

- `runF3City` 是纯函数（Node 里直接跑），只依赖 `Pt` / 多边形库，**没有 DOM**。
  搬进 Worker 只要把 `Scene` 用结构化克隆传回（`Float32Array` 可转移）。
- **收益**：主线程不卡，旋转 / 缩放全程流畅；配合 P1-1 可以做到"边生成边看"。
- **验收**：生成期间 `requestAnimationFrame` 间隔 < 20 ms。

### P2-1 禁区的图级重路由

- 现在禁区是"边界挖洞"。要做到"路绕着走"的下一步：把禁区作为
  `tensorLines` 的 **obstacle 场源**（张量主轴绕开禁区，流线在禁区外闭合），
  再在 `buildPathGraph` 里丢掉落在禁区内的边、用 `extendToNearest` 把断头接回。
- **验收**：禁区周边无度-1 节点（除尽端支路）；净区面积误差 < 1%；
  r=90 全城 ≤ 8 s。

### P2-2 多块净区

- `planZones` 目前只取最大一块。改成"按面积排序，> 5% 场地面积的都保留"，
  各自跑一遍路网再合并（`surfaceUnion` 一次）。
- **验收**：两块禁区把城市切成三块时，三块都有路网且面积误差 < 2%。

### P2-3 标线继续瘦身

- 虚线目前一段一个四边形；可以合并成"一条带 + 数组索引"（GLB 里同一材质一个 mesh，
  靠 UV/顶点色区分），减少 4000 个对象。
- **验收**：`merge: 'material'` 时 GLB < 2.5 MB（当前 3.57 MB）。
