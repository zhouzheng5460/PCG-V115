# 地块地面结构重构 · 计划与进度

> 目标来自你提的三点：**硬质铺装铺满整个街区（不用布尔）→ 上面叠一层互不重叠的地物 →
> 把"草地上的硬质铺装"和"内部路"合成同一类**。
>
> **进度（2026-11-09 已确认方案并开工）**
> - ✅ S1 L0 硬质底（`paver`，每街区一片，y=0.0095，零布尔）
> - ✅ S2 合并类：`paving / drive / hard` → `pave`（一处 `LotPatch.kind`，出口统一）
> - ✅ S3 同类合并认领：`takeMany()` 把 L 形绿化两条 + 三条沿边种植带**并为一次**认领
>   （1 次并集 + 1 次交 + 1 次差，替代 6 组 = 12 次布尔）
> - ✅ S4 停车外包：车位布局算完后，把车位线 / 通道端点投影到停车角度两轴取包络，
>   用这个矩形替换停车面（0 次布尔）；**替换前校验所有车位线端点都在矩形内**，
>   否则退回候选矩形（否则线会露到沥青外，`test/f3-road` 会抓）
> - ⬜ 水面：本轮只预留 `water` 类，不产出
>
> 现状量尺（r=90）：认领 **6835 → 3921 次（−43%）**；阶段④ **3.8 → 3.6 s**
> （墙钟收益不大，因为地下大头是停车求解 ~1.3 s 和建筑/树 ~0.8 s，不是布尔）。
> 打开方式：`F3_DEBUG=1` 会打印「认领 N 次 / 耗时 M ms」。

## 0. 落地后的四类地面（最终形态）

| 类 | 材质 | 图层 | 生成方式 |
|---|---|---|---|
| 硬质底 | `lotBase`（中性浅灰） | 街区硬质底 | **整个街区面一片**，零布尔、无任何切割 |
| 地块通路 | `lotPath`（浅土黄） | 地块通路 | 内部路 + 入口连接带 + 前场 + 街区级步行街（同一类） |
| 草地 | `lawn` / `grassLight` / `grass` / `grassDark`（四档深浅，按环 hash 分配） | 草地 | 地块 − 建筑 − 停车 − 通路；公园再按园路切开并圆角 |
| 停车场地坪 | `asphaltLot`（深灰） | 停车场地坪 | 车位布局的外包矩形 |

**互不重叠是结构性保证**：`groundForParcel` 末尾的 `enforceDisjoint()` 按
「停车 → 通路 → 草地」重新裁一遍（同类先并成一片，只做 2 次布尔）。
之所以需要这一刀：`surfaceSubtract` 失败时**不抛异常、直接返回被减数**，
一处失败整块草地就压在停车场上（实测 3.4 万 m²）。

回归：`test/f3-ground-layers.test.ts`（10 项）逐对求交，实测
**停车×草地 0.0 / 停车×通路 0.0 / 草地×通路 0.0 m²**，并断言
"地块里只允许这四类材质"。

> **踩过的坑（务必保留包围盒预筛）**：`surfaceSubtract` 对"本来就不相交"的输入
> 会原样返回（面积不变），如果把它当成"减法失败"再整片丢弃，草地会被删掉 89%
> —— 实测全城草地 118 000 → 13 000 m²，8/25 个街区一片草都没有。
> 现在的顺序是：**先按包围盒筛 → 相交才做布尔 → 面积几乎不变就原样保留**。
> r=90 实测去重叠只削掉 0.2% 的草地（417 454 → 416 692 m²）。

### 园路（公园）

每个公园 **1~4 条**园路，形态各不相同：在绿地内随机取一条**弦**
（`clipLineToSurface`），用二次贝塞尔往外鼓 8%~28%，缓冲成 0.75 m 宽的曲线带；
被切开的绿地块再用 `roundDomain(r=1.6 m, 3 段)` 圆角化。
随机数来自公园自己的 seed —— 同一座城每次都一样。

## 1. 现在的做法，以及它为什么会出这些问题

```
每个地块（parcel）
  ① 建筑占地 = footprints
  ② 剩余面 residual = 地块 − 建筑                （布尔 1 次）
  ③ 依次"认领"：前场铺装 → 停车 → 车道 → 绿化 → 余量硬铺
     每认领一块：intersect(候选矩形, remaining)  +  subtract(remaining, 候选)
                                               （每块 2 次布尔，一块地 6~8 次）
  ④ 碎片（<30 m²）转铺装；树按网格撒
```

三个直接后果：

| 现象 | 原因 |
|---|---|
| 地块里"缺一块"（黑底露出来） | 认领过程只要有一次布尔静默失败（`surfaceSubtract` 失败会**返回原面**），后面的差集就串了；最后没有兜底底板 |
| 草地上一道道硬铺装像"路" | 这些是 ③ 里的 `paving / drive` 片：入口到建筑的连接带、前场、碎片补丁。它们和"内部路"其实是同一种东西，只是走了两条代码路径 |
| 生成慢（阶段④ 占 65%） | 一块地 6~8 次布尔，全城 800 块 ≈ 6000 次 polygon-clipping |

## 2. 目标结构（分层，底层不参与布尔）

```
┌─ L2 地物层（每类一块多边形，互不重叠、按 y 递增绘制）
│    草地 / 停车场地坪 / 水面 / 内部路（含原"草地硬铺装"）
├─ L1 建筑占地（已有 solids，不在此列）
└─ L0 硬质底：**整个街区面**（block.surface 原样，一个环，零布尔）
```

关键约定：

1. **L0 永远铺满整块**。它不是一个"兜底"，而是设计：任何上层缺失/失败，露出来的也是硬质铺装，
   而不是底色或空洞。街区边界由路网已圆角的 `block.surface` 给出 —— 天然贴合。
2. **L1/L2 只做"叠加"，不做"认领"**。每类自己算形状、自己铺，彼此不重叠由**生成规则**保证，
   不靠反复求差。
3. **"内部路"和"草地硬铺装"合并为一个类**（暂名 `lotPave`）：
   - 数据上：`LotPatch.kind = 'pave'`，材质 `paver / stonePave` 二选一，
   - 语义上：它就是"地块内可走的硬质通路"（含入口连接带、前场、宅间通道、内部车行道），
   - 图层上：新增一组「地块通路」（`lotRoad:surf` / `lotRoad:walk` 合并展示，保留细分开关）。
4. **草地 = 街区面 − 建筑 − 停车 − 通路**：整块地**只做一次**差集，得到"剩余绿地"，
   再按 30 m² 门槛把碎片并入通路。这一刀替代原来的 6~8 次布尔。

## 3. 落地步骤

| # | 改动 | 影响面 | 预计收益 |
|---|---|---|---|
| S1 | `realize/ground` 增加 **L0 底板**：每块地 push 一个 `block.surface` 原环，材质 `paver`（y=0.010） | 只在 scene 里多 800 个面（合并后网格数不变） | 彻底消灭"缺一块"；视觉上先稳住 |
| S2 | 把 `paving/drive/hard` 三类统一成 `pave`（内部路），出口合并到 `pushGround` 一处 | `ground.ts` 的 `take()` 调用点、`layers.ts` 的图层映射 | 语义统一；为 S3 铺路 |
| S3 | 草地改成"一次差集"：`lawn = parcel − buildings − parking − pave` | `ground.ts` 主体 | 布尔次数 6~8 → 2~3；阶段④ 预计 5.1 s → 2.5 s 上下 |
| S4 | 停车仍独立（`asphaltLot`），但改为"先算车位排布，再取其外包多边形"，不再从 remaining 里扣 | `parking` 与 `ground` 的交界 | 停车与草地边界不再有锯齿 |
| S5 | 图层/导出跟着改名：`铺装与地面` → 「硬质底 / 草地 / 停车场 / 水面 / 内部路」；`GlbMerge` 的 `block` 分组不变 | `layers.ts`、导出面板文案 | 用户能单独关掉"内部路"看草地 |

顺序上 S1 先做（低风险、立刻见效），S2/S3 一起做（要改测试），S4 最后。

## 4. 验收判据

1. **无空洞**：全城任意采样点（每 2 m 网格）都必须落在 L0/L1/L2 某一层里 —— 现在只能靠"肉眼看"。
   写成一个测试：`每块地的 L0 面积 = block.areaM2 ± 0.5%`，且 `L2 各类两两交集 = 0`。
2. **体积账不炸**：`SceneIR` 面数增量 < 15%（L0 多 800 个面，但碎片补丁会少很多）。
3. **性能**：r=90 阶段④ 从 ~5.1 s 降到 ≤ 2.8 s。
4. **观感**：`out/ground-*.png` 前后对比 —— 草地不再被"硬铺装舌状条"切开；内部路与入口连接带同色同材质。
5. 现有回归全绿：`f3-layout / f3-landuse / layers / glb / f3-road`。

## 5. 风险与对策

| 风险 | 对策 |
|---|---|
| L0 与 L2 共面 z-fighting | 每层固定 y 阶梯（L0 0.010 / 草地 0.0126 / 停车 0.0128 / 通路 0.0130 / 标线 0.03），并在测试里断言"同 y 同材质不得重叠" |
| 草地"一次差集"失败 → 绿地消失 | 失败时退回"整块地铺草地"并在 notes 里报出地块 id（宁可全绿，不要空洞） |
| 合并 pave 之后图层开关粒度变粗 | 保留 `lotRoad:surf`（车行）/`lotRoad:walk`（步行）两个 id，只是生成时同一个类 |
| 导出分组变化影响下游 | `GlbMerge=block` 的分组键不变（仍是 `街区 + 大类`），只是 `地面` 里多了 L0 |

## 6. 需要你拍板的三件事

1. **L0 的材质**：`paver`（浅色人行道砖）还是 `asphaltLot`（深灰沥青）？
   现在草地上的硬铺装是浅色，我倾向 L0 用 `paver`，跟人行道同色系。
2. **停车场地坪要不要也铺在 L0 上**（即：停车场 = L0 硬质底 + 车位线，不再单独一块面）？
   铺的话少一层、更好合并；不铺的话停车场能有自己的深色。
3. **水面**：现在生成器里没有水体。是这一轮先只预留图层（不产出），还是顺带做一个
   "地块内小水面（雨水花园 / 池子）"的简单规则？
