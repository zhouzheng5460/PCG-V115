# F3 单链路版 · 架构与改动说明

> 这一版把产品收敛成**一套生成器 + 一个视口**。老的 Voronoi 城市（legacy）与
> Planner 已经不在产品链路上；道路生成只剩 F3 的张量场这一套。
> 性能与禁区的数字见 [`F3_PERF_ZONE_PLAN.md`](./F3_PERF_ZONE_PLAN.md)。

---

## 1. 现在只有一个生成器

```
城市边界（半径 + 种子 + 手画禁区）
  → 张量场路网（growStreetsTensor）
  → 道路几何（四级断面 + 路口 + 圆角 + 标线）
  → 街区（场地 − 路网面）
  → 张量一级切分 → 地块二级切分 → 用途（竞租场）
  → 建筑布局 / 复合地面 / 停车 / 树
  → Scene（面 / 体 / 线 / 道具）
  → 三维视口 & GLB 导出（同源）
```

**为什么删掉 legacy 与 Planner**

| 被删的东西 | 原因 |
|---|---|
| `mode=planner`（Planner 接管工业 / 多层住宅 / 零售） | 与 F3 是两套完全不同的规划哲学（候选集 + 评分 vs 规则直出），同屏比较没有意义；F3 已经是产品方向 |
| legacy 路网（`src/road/system.ts` 的 Voronoi 街网 + 独立标线） | 用户要求"不要有两个道路生成模式"。它的断面 / 标线 / 标注规则已被 F3 的 `roadgeom + markings` 取代 |
| `scene/build.ts`（legacy Scene 装配） | 没有 legacy 城市之后它没有输入了 |
| Canvas 2D 视口（`ui/view2d.ts`，1897 行） | 见 §3：性能与一致性都不如"正交投影的三维视口" |
| 2D 覆盖层（`ov:*`：地块轮廓 / 红线 / 中线 / 拓扑点 / R1 诊断） | 它们只是 2D 画布上的辅助线；对应的可视化已改为三维里的选中高亮 / 禁区 / 方向线 |

> `src/town/**` 里仍保留了一些 legacy 模块（`model.ts` / `modern.ts` / `planning/*` 的
> archetypes / typologies / realize 等）。它们**没有被产品引用**，只是 F3 依赖的
> 几何工具（`core/surface`、`subdivision/geom`、`roadgraph/*`）跟它们放在同一个目录树里，
> 一次性搬走风险大于收益。后续要清理时按目录整块删即可（`tsc` 会告诉你谁还在引用）。

## 2. 右栏：只留对 F3 真生效的参数

| 面板 | 参数 | 落到哪 |
|---|---|---|
| 城市 | 规模（半径）/ 种子 / 风貌 / 用途 / 密度 | `CitySpec`（boundary 半径、seed、style、program、density） |
| 禁区 | 工具（矩形/圆/多边形）/ 列表 / 用途 / 让距 | `CitySpec.zones` + `zonePadM` |
| 方向控制 | 画线 / 强度 / 列表 | `CitySpec.guides`（张量场 path 场源） |
| 建筑 | 楼高倍率 | `CitySpec.heightScale`（参与生成，不是渲染缩放） |
| 视图与导出 | 透视 / 正交顶视 / GLB 合并方式 / 导出 / 复制链接 | `View3D.setCameraMode`、`sceneToPrimitives({merge})` |

**被删掉的老参数**（在 F3 里没有对应物，硬接只会变成假开关）：
街区规模 `nPatches`、布局 `layout`（grid/field/radial/tensor）、地块切分模式与比重、
内部路网形态、停车 provider（legacy / placemaker / compare）、
S1 骨架 / Pattern Registry、单地块用途与切分覆盖、巷道宽 / 避障让距等 21 个 legacy 参数。

能对上就接的例子：**楼高**原来只是 3D 缩放（`heightScale` 乘在体块高度上），
现在进 `CitySpec`，层数会反过来影响退线、间距与体量 —— 所以改它必须重算。

## 2.5 编辑与重建是**分离**的两步

左边是"改"，右边是"算"，中间隔一个「应用并重建」：

| 动作 | 会不会重建 | 耗时 |
|---|---|---|
| 拖禁区角点 / 圆心 / 半径点 | 否 | 毫秒 |
| 拖方向线折点、改强度、删点 | 否 | 毫秒 |
| 改街区：切分方向 / 数量 / 类型 / 楼高 | 否 | 毫秒 |
| 点「应用并重建」（或 Ctrl+Enter） | **是** | 2~5 s，带遮罩 |
| 改种子 / 规模 / 风貌 / 用途 / 密度 | **是**（这几个就是"重新生成"） | 2~5 s |

顶栏中间会出现一条橙色应用条（`#applybar`），写着"有未应用的修改 · N 个街区覆盖"，
旁边是「应用并重建 / 放弃」。**放弃**回滚到上次生成时的编辑快照（`editSnapshot()`），
没生成的改动不会污染场景。

为什么不做"边拖边算"：生成在主线程同步跑，拖三下就要等十几秒、中间界面完全没响应。
现在的做法是拖动只改数据 + 重画覆盖层，用户确认后一次性算完。

## 2.6 选中之后能改什么

- **禁区**：用途（硬地 / 公园 / 林地）、启用、删除；**橙点**拖顶点（矩形 4 角 / 多边形逐点）、
  **蓝点**旋转、**绿点**整体缩放（圆是圆心 + 半径点），右键顶点删点。
  矩形一旦旋转会转成 4 点多边形 —— 轴对齐矩形表达不了斜置，转成多边形后还能继续逐点改。
- **选中街区会自动把镜头推过去**（顶视走正交缩放、透视走 target + 距离），聚焦半径按地块外接圆算。
- **方向线**：强度、启用、删除；拖每个折点，右键删点（最少 2 点）；面板底部可"清空所有方向线"。
  载入时会丢掉退化线（< 2 点或长度 < 2 m）—— 之前"场景默认多出一条蓝线"就是双击结束
  时落下了两个重合点。
- **街区**：
  | 参数 | 落到哪 | 说明 |
  |---|---|---|
  | 切分方向 | `blockOverrides[id].axisRad` | 改刀口朝向；场景里有一条虚线指示 |
  | 切分数量 | `.parcels` | **目标块数**（跳过张量一级切分，否则填 4 会变 17）；实测量级 ±20% |
  | 地块类型 | `.use` | 含**保留地**：路网照旧、只铺硬地不盖楼（区别于禁区：禁区连路都不进去） |
  | 建筑高度 | `.heightScale` | 乘在该街区的生成高度上（参与退线/间距，不是渲染缩放） |

## 3. 视口：一个 three.js 场景，两种投影

`src/ui/view3d.ts`

- `persp`：透视 + 阴影（原"三维预览"）
- `top`：**正交俯视 + 关阴影**（原"平面编辑"），滚轮缩放 / 拖拽平移，按 `z` 键或顶部页签切换

选中 / 高亮 / 标记全部画在三维场景里（`overlayGroup` / `selectionGroup` / `draftGroup`）：

| 内容 | 实现 |
|---|---|
| 禁区 | 半透明红面（`ShapeGeometry`，y=0.9）+ 轮廓线；禁用时不着色 |
| 方向线 | 蓝色折线 + 折点球 |
| 选中街区 / 禁区 | 蓝色半透明填充 + 亮蓝轮廓（`depthTest:false`） |
| 绘制草稿 | 橙色半透明面 + 轮廓，随鼠标实时更新 |
| 拾取 | 屏幕点 → 地面射线（y=0）→ 点内测试：禁区优先，其次街区 |

**为什么 2D 画布必须走**：一座 1.2 万面 / 2200 栋楼的城，2D 那套每帧遍历全量要素、
逐环描边、缩放重算描边宽度；三维本来就有深度缓冲与材质共享。更要紧的是
两个渲染器 = 两份选中逻辑 + 两套显隐判定 + 两块几何来源，"看到的"和"导出的"迟早不一致。
现在导出走的是同一个 `sceneToPrimitives`。

## 4. 导出的四种合并方式

`src/export/build3d.ts` 的 `GlbMerge`：

| 模式 | 分组键 | r=62 实测网格数 | GLB |
|---|---|---|---|
| `layer`（默认） | 铺装按 `group + 材质` 并；建筑保持独立 | 2113 | 5.12 MB |
| `material` | 材质颜色 | **30** | 3.57 MB |
| `block` | 街区号 + 大类（建筑/地面/道路/设施） | 78 | 3.61 MB |
| `none` | 每个要素一个节点 | 11587 | 12.11 MB |

街区号从要素名里取（F3 的命名是 `B12-T1-P3_house_0`）。
`block` 模式下每个街区出 4 组，进 DCC 可以逐块替换 / 做 LOD。

## 4.5 路口形状：为什么不再有"星形团块"

截图里那种"多条路交汇成一团黑块、还带尖刺"是两件事叠出来的：

1. **图错了**：张量流线在小角度相交、`extendEnds` 把断头拉到红线上又跟别的线交叉，
   同一小片区域里出现 3~5 个路口。`src/f3/graphclean.ts` 做三件事：
   短路收缩（< 9 m 的两路口合并）、节点聚类（14 m 内合并到质心）、锐角去重
   （同向 20° 内的短臂删掉，且只在不会孤立对端时删）。清理后最大度 ≤ 4，
   边数只减不增（`test/f3-overrides.test.ts` 有断言）。`?f3clean=0` 可以关掉 A/B 对比。
2. **几何错了**：`starZone` 原来用"各臂收头线 + 转角圆弧"手工拼环，嘴距常常越过转角交点，
   圆弧外那块三角形就成了戳进街角的沥青尖刺。现在改成**各臂口部端点的凸包**：
   凸包天然是简单多边形（不自交、不凹），形状语义也对（路口就是把各条路的断面包起来）；
   凸包的"非口线"那条边（两臂之间）中间往内收一点做圆角，标记线的路缘石边线也从这些边派生。
   实测最大路口面 2329 m² → 987 m²，长宽比全部 ≤ 4。

## 4.6 路口路缘线（标线）三处修正

截图里那根"断了一截、还飘在铺装上"的白线，是三个独立问题：

| 现象 | 根因 | 现在 |
|---|---|---|
| 白线中间断开 1~2 m | 按"每个转角两头各算一次内移"再拆 4 段，接缝处法线不一致 | 沿整条环**只算一次 miter 内移**，相邻段共享端点，连续 |
| 白线飘在铺装上 5~7 m | 线是从"路口让开区"派生的，而**最终路口面是 `车行面 ∩ 让开区`**，街角那块被裁掉了 | 改为从**最终路口面**派生（内移 0.42 m），并逐边判断"外面是不是接着一条路" |
| 路口内部横着几根白线 | 斑马线/停止线按解析收头距离摆，而路口面按凸包算出的嘴距更远，于是落进了路口里 | 标线改用**路口面自己的实际嘴距**（`starZone` 的 L 回传给标记线） |
| 路口边线段数 2300+，生成慢 40% | 2 m 切一段，每段独立三角化 | 一个转角一条折线（每城 ~200 段），并加断言防止回退 |
| 路口中心一个**圆孔**、路口变成圆饼、人行道破面 | 早期 `starZone` 用"星形多边形"，后改凸包时把 `out.length < 6` 当有效性判据 —— 十字路口凸包只剩 4 个极值点，**70/82 个路口被判死、退回 `diskOf` 圆盘** | 判据放宽到 `>= 3`（0 个回退）；凸包点改为**转角圆弧采样点**（与人行道同半径、同采样密度） |

## 4.7 GLB 的目录层级

导出的节点树（`城市` 是唯一根，叶子是 mesh）：

```
城市
├─ 街道            车行道 / 路口 / 人行道 / 标线
├─ 街道设施        路灯 / 护栏 / 行道树 / 车位线
└─ 街区
   ├─ 城市底图
   ├─ B01
   │  ├─ 建筑       ← 每栋一个叶子节点（`B12-T1-P3_house_0`，可追溯）
   │  ├─ 地面铺装    硬质底 / 地块通路 / 草地 / 停车坪 / 水面
   │  └─ 植物
   └─ B02 …
```

- 层级由 `Primitive.path: string[]` 驱动（`build3d.ts` 的 `pathOf()`），
  `glb.ts` 按路径建组节点，组节点只有 `children`、叶子只有 `mesh`。
- 合并方式仍可选，但目录会跟着变：
  `material` → `城市/按材质/<材质>`；`block` → `城市/街区/<Bxx>/<大类>`；`none` → 逐要素建树。
- 命名：合并后的网格叫 `街区_B12_地面铺装_草地_18` 这种"路径_数量"，
  未合并的建筑保留 `B12-T1-P3_house_0`（导进 DCC 能顺着编号找回是哪块地）。

## 4.8 禁区：生成之后**局部**生效

禁区不参与城市生成，而是生成完再叠一层（`src/f3/zoneapply.ts`）：

```
基础城市（按"无禁区"生成并缓存）
      ↓ applyZonesToCity(base, zones, { padM, padPave })   ≈ 60 ms
⓪ 路面：**只按禁区本体**裁（车行面/人行道/路缘做布尔，标线整段丢）
① 建筑：与禁区（含让距）相碰 → 整栋删（不切分）
② 地块地面 / 树：质心落在范围内 → 删
③ 范围 ∩ 街区块 → 铺一层地面（硬地 / 公园草地 / 林地，可补树）
      ↑ 让距不碰路面
```

| 以前（扣边界） | 现在（后处理） |
|---|---|
| 改一个禁区 → 整城重算 2~6 s，路网重排 | 改一个禁区 → **80~130 ms**，只有禁区碰到的路面被挖掉 |
| 路会在禁区边缘断头、整城几何跟着变 | 只有禁区本体范围内的路面消失（让距不切路） |
| 让距同时作用于路网与地块 | 让距**只作用于地块**（不跨街区、不影响道路） |

「让距」旁边有一个**衔接铺装**开关（`zonePadPave`，默认开）。开启后，让距环带
（`让距范围 − 禁区本体`，裁到街区里）不是一块光板，而是按条带生成过渡地：

- 中间一条 **1.6 m 内部步道**（`lotPath`），沿环带主轴走；
- 环带宽度 ≥ 9 m 时，一侧留 **5 m 深停车带**（`asphaltLot`）+ 每 2.5 m 一根车位线；
- 剩下的部分铺**草地**，沿步道每 9 m 补一棵树；
- 所有几何都裁回环带片自身，永远不会溢出到道路或禁区里。

关掉则只按禁区本体铺，保持原本的地面样式。

坐标 y：禁区铺装压在地块地面之上（0.0142）、标线之下，所以不会被草地盖住。

## 4.9 编辑一块地只重算这块地

`groundForParcel` 是全城最贵的一步（阶段④ 的 70%：每块地十几次布尔）。现在按
**"地块几何 + 建筑 + 输入参数"签名**缓存结果（`groundCache`，上限 6000 条）：

- 改某个街区的切分方向 / 数量 / 用途 / 楼高 → 只有那个街区的地块重算，
  其他地块直接命中缓存（实测 **424 命中 / 22 未命中**）；
- 实测 r=80：冷启动 8.99 s，改一个街区 **3.89 s**（剩下的主要是路网那一段）。

调试：`F3_DEBUG=1` 会打印 `缓存命中 N / 未命中 M`。

## 4.10 小城市路口圆角：试过的两条路

现象：半径 40（≈0.28 km）时，路口转角的人行道出现针状尖刺 / 环带收成尖点。

**原因**：四层断面（B0 车行 / B1 路缘 / B2 人行 / R 用地）各自圆角，靠"同心弧"
保证环带等宽；而 fillet 的切距有上限 `t = r/tan(θ/2) ≤ 44% 最短邻边`。
小城里街区边短、路口尖，`r+w₂` 撞上限而 `r+w₁` 没撞 → 两层弧不再平行 →
差集 `B2 − B1` 留下退化三角与针尖。大城边长 100 m+，夹子永不触发，所以只在小区间暴露。

**试过 A（失败）**：只圆最内层，外层用 `surfaceOffset` 逐级派生。
`surfaceOffset` 对"几万顶点、上百洞的并集"经常 `surfaceValid` 判自交 → 返回空 →
路缘层整层消失、人行道宽度乱跳。**这条路在当前 offset 实现下走不通**。

**采用 B（已落地）**：
- 每个路口先算"放得下的半径" `0.42·最短邻边·tan(θ/2) − 全断面宽`，**下限 9 m**，
  用它压 `cornerRFor` → 四层不再撞内层夹子，弧恢复同心；
- 下限为什么是 9 m：压到 5 m 时锐角分叉口的两侧弧会贴成一条**细丝**横在路口里。

结果：r=90 的 41° 分叉恢复正常；r=40 的大尖刺与收尖消失；只剩最尖几个角上有
1~2 m 的小台阶。

**要彻底根治**仍需 A 的构造，但必须先把 `surfaceOffset` 换成健壮的多边形偏移
（clipper 那类）：偏移可靠之后 B1/B2/R 由 B0 逐级长出来，天然嵌套，任何角度都不会有针。

## 4.11 布尔与偏移换成 Clipper2（4.10 里被卡住的那一步）

4.10 的结论是"要根治得先把 `surfaceOffset` 换成健壮的偏移"。这一步做了：
接入 **Clipper2**（`clipper2-ts`，BSL-1.0，纯 TS，无 WASM），封装在
`src/core/clipper.ts`，对外只有 5 个函数（偏移 / 并 / 差 / 交 / 拆自触环）。

### 换掉了什么

| 位置 | 原来 | 现在 |
|---|---|---|
| `surfaceOffset` | 自己写的 `buffered()` + 自交检查 | Clipper2 `inflatePaths`（整数内核 + 内置拓扑清理） |
| `surfaceUnion/Subtract/Intersect` | polygon-clipping (martinez) | Clipper2，旧实现保留为兜底 |
| roadgeom 的 `unionPolys/diff/cap/clipBatch` | 同上 | Clipper2 优先，失败落回旧路径 |
| 扣街区 `buildBlocks` | `场地 − 路网面` | `场地 − cutDomain`（见下） |

开关：`F3_BOOL=legacy` 一键切回旧引擎做 A/B 与回退。

**单位与精度**：1 世界单位（7 m）= 10000 格，1 格 = 0.7 mm。
不能取 7 mm —— 代码里有"微偏移破退化"的用法（并集失败后把面外扩 5 mm 再并一次），
7 mm 的格子会把它抹成 0，那个重试就变成"什么都没做"。

### 踩到的四个坑（每个都真出过问题）

1. **不能混用两个引擎**。先只把 `surfaceOffset` 换成 Clipper，布尔仍走 martinez：
   Clipper 产出的路网面（含共线边）喂给 martinez，街区被并掉 —— 结构化城 20 → 12 个。
   结论：整体切换，一格都不许混（唯一例外见第 3 条）。
2. **路面精确裁在红线上 = 发丝缝**。布尔量化后路面与红线差 0.7 mm，外围街区顺着
   这条缝连成一圈：campus 9 个街区并成 3 个，最大一块 33 万 m²、只有 11 个顶点。
   修法：**只给扣街区**单独圆角化一份**未裁**的路网面（`RoadGeom.cutDomain`）。
   可见面必须仍旧"先裁后圆" —— 圆角对凸角是**削掉**材料的，顺序反了会把红线
   附近的转角削进场地（实测一个路口中心因此掉到路面外）。
3. **Clipper 不拆"自己碰自己"的环**。`sanitize` 原来靠 martinez 的并集把自交环
   拆成简单环，换引擎后失效（11 个自交环进三角化 = 尖刺）。修法：新增
   `splitPinched()` 按重复顶点拆环；`sanitize` 的修复路径**只**借旧引擎一次。
   街区也要拆：R01 样板两个街区并成一个 15259 m² 的"8"字环，被判成 park、0 栋楼。
4. **NaN 会从质心一路传到容积率**。某块地轮廓退化 → `centroidOf` 出 NaN →
   `centerDist` NaN → 层数 NaN → 整城 `gfaM2 = NaN`。在 `height.ts` / `blocks.ts` /
   `build.ts` 三处加了非有限值护栏（`NaN <= 0` 是 `false`，原来的 `hU <= 0` 挡不住）。

### 结果

- **布尔静默失败：453 次 → 0 次**（旧引擎每出一座城报 453 次
  `Tried to create degenerate segment at [NaN, NaN]`，而它的兜底是 `return 原值`，
  等于那一刀没切）。这条现在是 `f3-road.test.ts` ⑩ 的常驻断言。
- **生成快 44%~63%**（r=62，同参数同 seed）：

  | 风貌 | 旧引擎 | Clipper2 |
  |---|---|---|
  | structured | 5308 ms | 2994 ms |
  | organic | 5406 ms | 2165 ms |
  | campus | 3024 ms | 1128 ms |

- **街区与旧引擎逐块一致**（面积集合完全相同：26 / 34 / 12 块），说明换引擎没有
  偷偷改变城市结构。
- 包体 +71 kB（gzip +19 kB）。

### 还没做的

A 构造（只圆 B0、B1/B2/R 由它逐级偏移）现在**技术上可行了**，但还差一步：
断面宽度是**按道路等级**变的（主干 17 m / 次干 12 m / 支路 8 m），一次全局 delta
不够用，需要 Clipper 的 `executeWithCallback` 做**逐顶点变距偏移**。
当前分层仍是"四层各自缓冲 + 各自圆角"，靠 4.10 的 B 方案保证同心。

## 4.12 路口路缘标线：改成"沥青边界整体内缩"

现象（用户第四次报）：路口转角那条白色弧形边线是**折线**，而且会有一条斜线
**穿进路口**，形成 V 形。

### 根因有两层

1. **线沿错了边界**。上一版从"路口面"（`B0 ∩ 让开区`）的多边形边界派生：
   逐顶点沿法线内移 0.42 m，再 Chaikin 平滑两次。但路口面的边界有一半是
   **口线**（路在这里继续，横断线是**直弦**）—— 拿它当路缘画，弦就变成了白线。
   截图里那个 V 形就是两条弦。
2. **边界本身就不圆**。`arcSegsFor` 按每段 2.6 m 切弧，6 m 半径的 90° 转角只有
   4 段（下限又抬到 6 段）→ 每段转角 15°，特写下就是个多边形。
   **标线不可能比它所在的边界更圆**：偏移是同点数的平行曲线，Chaikin 只会磨角、
   还会把弧往里收。

### 改法（用户提的那条：偏移下边界）

- `jedge` = **车行面 `drive`（= carriage ∪ junction）整体内缩 0.25 m 的边界**。
  Clipper 的 `inflatePaths` 给的是平行曲线：转角弧偏完还是弧，天生不会穿进沥青，
  而且不再有"口线"这个概念（∂drive 在路口喉部是连续的）。
- 只保留落在**路口节点附近**（外圈转角半径 + 5 m）的那几段：直路段已经有车道
  边缘线，这里只补路口转角这一圈。判据不能用"落在让开区里"—— 让开区的转角边
  就是直弦，用它过滤会把大的凸角整个排除（实测 4 个角只有 1 个有线）。
- 内缩量抽成常量 `EDGE_INSET_M = 0.25`（`lanes.ts`），和车道边缘线**共用一个数**：
  两段线是同一条白线的两截，差 17 cm 就会在停止线处错一个台阶。
- `arcSegsFor` 从每段 2.6 m 加密到 **1.0 m**（6 m 半径 10 段、12 m 半径 19 段）。
  这是根本：只要边界是 6 条弦，任何算法都画不出圆。

### 结果

- 标注段：371 条 / 多数只有 2 个点（一条直弦）→ **171 条 / 平均 46 个点**。
- 断言改写：`jedge` 每个顶点到 `carriage ∪ junction` 的边界距离必须是
  **0.25 ± 0.35 m** —— 越界 0 段（旧断言比的是"贴路口面边界"，那正是病根，
  等于把错误当标准）。
- 代价：转角弧加密让出城从 2.99 s 涨到 ~3.1~3.5 s（顶点数翻 3~4 倍，布尔更贵）。
  换来的是沥青转角本身也不再是 6 边形。
